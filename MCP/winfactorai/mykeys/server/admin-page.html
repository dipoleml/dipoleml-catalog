📖 使用说明（启动方式 · 给 AI 用 · 测试令牌）

1️⃣ 怎么启动本管理台

  • 独立启动（不依赖 ZCode，重启电脑后需重新执行）：
    ~/.zcode/cli/plugins/cache/mkeys-local/mkeys/0.1.0/bin/mykeys.js admin
    启动后终端打印带令牌的访问地址，复制到浏览器打开即可；18765 端口被占时自动换端口（以打印为准）。
  • ZCode 会话内：输入 /mykeys-admin，或直接对 AI 说「打开 MyKeys 管理页面」。
  • 访问令牌持久化在 ~/.mkeys/admin.token（0600 权限）：服务重启后地址不变，收藏一次长期有效；仅本机可访问，请勿把带令牌的地址外传。

2️⃣ 怎么给 AI 使用凭据

  • 新会话里直接说人话，例如：
    「用 jira-cli 的令牌，查一下我名下未关闭的 issue」
    「Jira 上 DBMPRO-59 现在什么状态，把评论也拉出来」
    AI 会自动调用 get_token 取临时令牌去请求，不需要你手动复制令牌。
  • AI 取令牌必须填写用途（不填会被拒绝），每次取令牌/验证/读密钥都自动记入审计日志。
  • 查账：输入 /mykeys 或问「密钥最近被用了多少次、用来干什么」；本页下方的统计图表就是同一份数据。
  • 令牌只在 AI 当次任务的内存里使用，不写入代码和文件，过期自动重新签发。

3️⃣ 怎么测试令牌是否正确

  • 点凭据行的「验证」按钮 = 真实登录校验：向验证地址发一次带令牌的请求。
    ✅ HTTP 200 → 令牌有效；❌ 401/403 → 令牌错误或已在目标系统轮换，需重新生成并编辑凭据更新。
  • 点「签发令牌」可完整走一遍 AI 取令牌的流程（需填用途），用于端到端测试。
  • api-key 类型认的字段名是 apiKey（或 token / key）；字段名不对会提示「缺少 apiKey/token/key 字段」。
  • 验证地址有讲究：要选「带令牌 200 / 不带 401」的接口（如 Jira 的 /rest/api/2/myself），填系统首页会永远 200 测不出问题。
