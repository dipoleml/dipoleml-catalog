ODL의 기본·plain + HTML 옵션을 유지했고, OCR을 끈 native-off는 같은 200문서·정답·평가기의 추가 진단 트랙이다. NID 200, TEDS 42, MHS 107의 모수와 누락 0은 모두 같다. 041의 잘못된 제목·문단 분리는 개선된다. 116은 감지한 줄바꿈 캡션이 기존 캡션 굵게 출력 정책을 거치면서 기본/native NID가 소폭 낮아진다. 캡션 감지기와 Markdown 정책, 표 셀은 바꾸지 않았다. TEDS·MHS는 동일하다. 이 때문에 모든 점수가 개선됐다고 보고하지 않는다.

HWPX의 남은 16건은 무효 GT 격자 14건과 수식 열을 빈 열로 접은 GT 2건이다. [원본 대조](hwpx-table-original-audit-2026-09-30.json)를 유지하며, 수식을 지우거나 GT·모수를 바꿔 100%를 만들지 않는다. HWP5 쌍의 100%와 HWPX 자체 99.8378%는 별도 지표다.

PDF는 실제 본문 서체·크기, 어절 줄바꿈·중일문 경계, 번호 문단, 패널 아래 이어지는 본문과 쪽 번호 사이의 다중 페이지 표를 처리한다. #115·#118 원본 PR 커밋 이력을 보존해 병합했고, 반복 머리글·세로 병합 값 및 독립 양식·단위 행을 검증했다. 제보된 327쪽 책의 동일 원본은 확보하지 못했으므로 #112·#113 해결을 주장하지 않는다.

공문서 GFM 표는 실제 표시문자를 한 번 해석하고 표 안에서 폭 계산을 재사용한다. 301행×6열 보고서 공개 생성 API의 고정 ZIP 엔트리는 동일하며 중앙값은 18.101917→17.666875ms(2.4% 감소)다. 내부 300행×6열 측정은 23.969042→22.009084ms(8.2% 감소)다. 버전별 별도 프로세스 3회에서 생성 중앙값의 중앙값은 15.901666→15.458209ms, peak RSS 중앙값은 139,722,752→135,577,600바이트다. 이 수치는 해당 표 입력의 측정이며 전체 문서 성능 보장은 아니다.

렌더는 바탕쪽·머리말·꼬리말, 페이지 레이어·zOrder, 삭제 범위, 선분 곡선·그라데이션·TOTAL 그림 채움과 도형 회전을 처리한다. 최종 dist의 공개 crop API와 래스터 11개 대조에서 가림 뒤 노출되던 사진 픽셀을 제거했고 삭제 사진은 추출하지 않는다. 글앞 사진 안의 후속 본문 글은 0픽셀이며, 기존 바깥쪽 정수 반올림 crop 가장자리에는 사진 밖 28픽셀이 남는다. 회전 글상자·중첩 회전의 영역 좌표, 독립 캡션 story의 삭제 범위와 문단 번호도 회귀 테스트로 보존한다.

삭제 마커가 없는 원문에서만 준비 순회를 생략한다. 같은 소스의 강제 순회/생략 대조는 SVG·scene 동일, 94.7705→91.526375ms(3.42% 감소)다. 4.17.3 대비 전체 표 렌더는 96.336625→97.676125ms(+1.39%)로, 일반 렌더 가속을 주장하지 않는다. native PDF 4문서의 진단 시간 변화도 일반 파싱 가속으로 확대하지 않는다.

검증된 곡선은 LINE seg, 그림 채움은 TOTAL이다. 전체 renderingInfo 변환 행렬과 사진·컨테이너 회전은 후속 검증 대상이다. 한컴 GUI 시각 오라클은 미실행이며, 기존 사용자의 명시적 배포 진행 지시를 유지한다. OCR 표 정확도·일부 ODL 구조와 한국 PDF 띄어쓰기 등 99 미만 지표가 남아 있다.
