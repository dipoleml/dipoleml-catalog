# 공문서(公文書) 생성 스킬

내용·주제를 받아 **한국 행정 공문서 표준 서식의 HWPX**로 생성한다.
서식 표준은 행정안전부 「행정업무운영편람」·「행정업무의 운영 및 혁신에 관한 규정」 시행규칙 근거.
실제 렌더링(항목부호 행갈굼·여백·폰트)은 kordoc 공문서 모드(`kordoc generate --preset`)가 담당하므로,
이 스킬은 **(1) 종류 판별 → (2) 구성 설계 → (3) 마크다운 작성 → (4) 게이트(윤문·구성 검수) 통과 → (5) 변환 → (6) 경로 안내** 를 한다.
결재권자가 "사람이 생각해서 쓴 문서"로 읽게 하는 것이 목표다 — 서식보다 **논리 구조와 문체**가 먼저다.

## 절차

### 0. 견본이 있으면 이 스킬을 쓰지 않는다

사용자가 견본 HWPX/HWP 를 주며 "이 서식대로/똑같은 양식으로/이거처럼" 새 문서를 원하면 프리셋으로 다시 짜지 말고 견본을 고쳐 쓴다:
`kordoc 견본.hwpx --keep-layout-tables -o 견본.md` → 골격(표지·결재란 표, 제목, □·ㅇ·- 부호, 강조, 표 표기, 이미지 줄)은 두고 내용만 새로 쓴 마크다운 →
`kordoc patch 견본.hwpx 새문서.md -o 새문서.hwpx` → `kordoc render` 로 확인. HWPX 견본은 줄을 늘리고 줄여도 같은 부호 견본 문단 서식으로 들어간다.
(MCP: parse_document keep_layout_tables → patch_document → render_document)

### 1. 문서 종류 판별 → 프리셋

| 사용자 의도 | 프리셋 | 항목부호 | 비고 |
|------------|--------|----------|------|
| 대외 공문/시행문 | `기안문` | 8단계 `1. 가. 1)` | 두문·본문·결문 |
| 정책·검토·결과 보고 | `보고서` | 불릿 `□ ○ - ㆍ` + 헤딩 | 개조식, 1건1매 |
| 사업·행사 계획 | `계획서` | 8단계 | 5W2H 골격 |
| 알림·통지·안내 | `통지` | 8단계 | 경어 종결 |
| 회의 기록 | `회의록` | 8단계 | 법정 9요소 |
| 중앙부처 업무보고·국회 서면보고 | `업무보고` | `□ ㅇ - *` + 장 띠·절 숫자칸·① 항목 띠 | 재경부 실측(v4.14), 키워드 파랑 |
| 지방 방침서·추진계획(시장·부시장 방침) | `서울방침` | `□ ㅇ - ▸ ※` + [Ⅰ] 장 상자·절 띠·❶ 과제 | 서울시 시장방침 정답지 5건 실측 |

의도가 모호하면 `AskUserQuestion`으로 종류를 확인한다. (예: "보고서로 할까요, 대외 시행문(기안문)으로 할까요?")

**보고서·계획서 계열이면 스타일을 반드시 먼저 묻는다** (`AskUserQuestion` 한 번):
- **정부(중앙부처) 스타일** → `업무보고` — 표지·목차, 장 띠, 절 숫자칸, ① 항목 띠, 함초롬바탕 15 (재정경제부 업무보고 실측)
- **지방(서울시) 스타일** → `서울방침` — 제목표(파랑 부제·담당자 행)·요약박스, [Ⅰ] 장 상자, 절 띠, ❶ 과제, □ HY견고딕·ㅇ 한컴돋움 (서울시 시장방침 실측)
- 1쪽 요약보고처럼 간단한 문서면 `보고서`도 선택지로 둔다. 기안문·통지·회의록은 법정 서식이라 묻지 않는다.

### 1-1. 구성 설계 — 쓰기 전에 논리부터 (보고서·계획서 계열 필수)

본문을 쓰기 전에 아래를 먼저 정한다. 상세 기준과 실측 근거는 `references/logic.md`.

1. **보고 목적 한 문장**(두괄식) — "무엇을, 어떻게 해서, 어떤 목표치로 하고자 함". 제목 바로 뒤 `> …하고자 함` 요약이 된다.
2. **문서 꼴 → 뼈대** — 서론·본론·결론은 장 이름으로 드러낸다. "서론·본론·결론"이라고 쓰지 않는다.
   - 개선방안 보고: 추진배경 → 현황 및 문제점 → 개선방안 → 추진일정·소요예산 → 기대효과 → 행정사항
   - 추진계획: 추진배경·근거 → 추진개요(기간·장소·대상·예산) → 세부 추진계획 → 소요예산 → 추진일정 → 행정사항
   - 검토보고: 검토배경 → 주요내용(쟁점) → 검토의견(대안 비교·권고안) → 조치계획
   - 결과보고: 관련근거 → 개요 → 추진결과(실적·수치) → 성과와 한계 → 향후계획
   장은 사안에 필요한 것만 둔다. 실결재는 장 3~5개로 짧다 — 빈 장을 채우려고 일반론을 쓰지 않는다.
3. **논리 사슬** — 장과 장이 이어져야 설득된다.
   - 배경은 **사실**로 연다: 지시(일자)·법령 개정(시행일)·민원·사고 건수. "급변하는 환경에 따라"로 열지 않는다.
   - 문제점은 현상과 원인을 가른다: "야간 단속 공백(원인: 주간 순찰 인력 4명)".
   - **문제점마다 방안 한 짝**, 같은 순서로. 방안 첫머리에 `(○○ 공백 해소)` 처럼 어느 문제에 답하는지 적는다.
   - 방안마다 대상·수량·기한 → 일정·예산 장에서 언제·얼마·누가가 닫힌다.
   - 기대효과는 문제점에서 든 지표의 **목표치**("민원 412건 → 200건(51%↓)"). "만족도 향상·체감도 제고"는 쓰지 않는다.
4. **결재권자 예상 질문**에 문서가 미리 답하는지 본다: 왜 지금인가 · 근거 법령은 · 얼마 드나 · 누가 하나 · 다른 방법은(대안 비교) · 위험·반대는.

수치·이름·일자를 모르면 지어내지 말고 `○○건`·`2026. ○. ○.` 자리표시로 두고 채울 항목으로 안내한다.

### 2. 템플릿 로드 + 내용 채우기

해당 `templates/<종류>.md`를 Read로 읽어 골격을 파악하고, 사용자 내용으로 채운다(`서울방침`은 `templates/서울방침.md`).
- **부족한 필수 정보**(기관명, 수신처, 담당자·연락처, 시행일 등)는 사용자에게 묻거나, 모르면 `○○○`/`[기관명]` 같은 **플레이스홀더**로 두고 "채워야 할 항목"을 마지막에 안내한다. 임의로 지어내지 말 것.
- 본문은 아래 **표기법**과 **항목부호 규칙**을 반드시 지켜 작성한다.

### 3. 마크다운 작성 규칙 (kordoc 공문서 모드가 인식하는 형식)

**항목부호 = 중첩 리스트의 깊이로 표현.** 마커 종류(`-`/`1.`)는 무시되고 **깊이 → 부호**가 강제된다.
들여쓰기 **2칸 = 한 단계**.

```
1. 첫째 항목 내용          ← 깊이0 → "1."
  - 둘째 항목              ← 깊이1(2칸) → "가."
    - 셋째 항목            ← 깊이2(4칸) → "1)"
      - 넷째 항목          ← 깊이3(6칸) → "가)"
2. 다음 첫째 항목          → "2."
```
- 깊이별 부호: 0=`1.` 1=`가.` 2=`1)` 3=`가)` 4=`(1)` 5=`(가)` 6=`①` 7=`㉮` (자동 생성·자동 정렬)
- **항목이 하나뿐이면** 리스트로 만들지 말고 본문 단락으로 바로 쓴다(규정: 단일 항목은 부호 생략 — 엔진도 자동 생략하지만 구조를 단순히).
- **보고서**(`--preset 보고서`)는 리스트 깊이가 `□ ○ - ㆍ` 불릿으로 나오고, 대제목/중제목은 `#`/`##` 헤딩으로 쓴다.
- **가운데 정렬**(행정기관명·발신명의)은 `<center>광 진 구 청</center>` 한 줄로.
- **제목/기관명**은 `#`(h1) — 공문서 모드에서 가운데·크게 렌더된다.

### 4. 표기법 (본문 작성 시 직접 지킬 것 — 엔진이 안 고쳐줌)

| 항목 | 규칙 | 예 |
|------|------|----|
| 날짜 | `YYYY. M. D.` 온점+1칸, 월·일 0 제거, **끝에도 온점** | `2026. 6. 19.` / `2026. 6. 19.(금)` |
| 기간 | 물결표 `∼` | `6. 1.∼6. 15.` |
| 시각 | 24시각제 `HH:MM`, 시·분 0 표기 | `09:00`, `14:30` |
| 금액 | 숫자+한글 병기, 붙여씀 | `금113,560원(금일십일만삼천오백육십원)` |
| 붙임 | `붙임` 뒤 2칸(쌍점 X), 1개면 번호 생략 | `붙임  ○○○ 1부.  끝.` |
| 끝 | 본문/붙임 마지막에 2칸 띄우고 | `…바랍니다.  끝.` |
| 법령명 | 낫표 | `「행정업무의 운영 및 혁신에 관한 규정」` |
| 쌍점 | 앞 붙이고 뒤 1칸(본문·항목). 표 셀의 라벨 "성 명 :"은 법정 서식 관행이라 lint 대상 아님(v4.12.3) | `일시: 2026. 6. 19.` |
| 어투 | 시행문·통지=경어("~하시기 바랍니다") / 보고서·계획서=개조식 명사형("~함/~임") | |

**생성형 AI 문체 흔적(슬롭) 제거** — 처음부터 이렇게 쓴다 (`kordoc lint --gate` 가 `AI_*`·`SLOP_*` 룰로 잡는다):

- 결산 접속어(결론적으로·요약하면·정리하면)와 평론 상투구(시사하는 바가 크다·주목할 만하다·본질적으로)는 쓰지 않는다
- 체감·만족도 상투구(체감도 높은·만족도 향상·삶의 질 제고) 대신 무엇이 얼마나 나아지는지 수치로
- 강화·제고·구축·활성화로 끝나는 줄에는 대상·수량·기한을 붙인다("협업체계 구축" → "경찰서·소방서 합동점검 월 1회")
- 시대 상투 서두(급변하는·중요성이 날로·4차 산업혁명 시대)·과장어(획기적·한 단계 도약·패러다임 전환)는 사실로 바꾼다
- 줄표(— – ―)는 쉼표·괄호·가운뎃점(·)으로, 강조(볼드)는 리드어·핵심 수치 한 곳만, 그림 문자는 쓰지 않는다
- 번역투(에 있어서·되어지다·가지고 있다·에 대해서)·"A, B, 그리고 C"·줄 첫머리 "이는·이러한"을 풀어 쓴다
- 외래어는 행정용어로 옮긴다 — 파일럿→시범, 베이스라인→기준치, 리스크→위험 요인, 벤치마크→준용, 투트랙→병행

상세 표준은 `references/reference.md`(전체), 빠른 참고는 `references/quickref.md`.

### 5. 게이트 → 변환 → 저장

작성한 마크다운을 임시 파일로 저장한 뒤 **게이트를 통과할 때까지 고쳐 쓴다** — 지적을 무시하고 변환하지 않는다:

```bash
npx -y kordoc@^4 lint <작성.md> --gate --preset <종류>   # 미통과면 exit 1 + 지적 목록
```

- 표기법·문체 error, 윤문(`SLOP_*`)·구성(`LOGIC_*`) 지적이 하나라도 있으면 미통과다. 지적마다 원인을 고쳐 쓴다(낱말만 바꿔 피하지 않는다 —
  `LOGIC_EFFECT_VAGUE` 면 목표치를, `LOGIC_PROBLEM_UNANSWERED` 면 그 문제의 방안을 쓴다).
- 사실이 없어 못 고치는 자리는 자리표시(`○○건`)로 두고 채울 항목으로 안내한다 — 자리표시는 통과한다.
- 통과하면 변환한다(`--gate` 를 붙이면 변환 직전에 한 번 더 막는다):

```bash
npx -y kordoc@^4 generate <작성.md> -o <출력.hwpx> --preset <종류> --gate
```
(kordoc 저장소 안에서 작업 중이면 `node dist/cli.js generate …` 도 된다)
(또는 라이브러리: `markdownToHwpx(md, { gongmun: { preset } })`)

옵션: `--font gothic`(맑은 고딕, 전자결재 스타일) / `--pt 14` / `--line-spacing 130`.

**위계 폰트(`--levels`, v4.12.3)** — 항목부호 단계(depth 0~7)마다 글꼴·크기·굵기를 지정한다. 실측
(실결재 기안문 206건·보고서 337건, `references/reference.md` 2.7) 근거의 처방:

| 문서 꼴 | 실측 지배 관행 | 처방 |
|---|---|---|
| 법정 8단계 기안문(1. 가. 1)) | 전 단계 본문과 동일 글꼴·크기(90%) | **지정하지 말 것** (기본값) |
| 전자결재 기안문·계획서 □/ㅇ/- 계열 | □ HY견고딕 +2~3pt 굵게 · ㅇ 한컴돋움 굵게 · - 휴먼명조 본문 | `--preset 계획서 --bullet2 ㅇ --levels "0=HY견고딕/17/bold,1=한컴돋움/15/bold,2=휴먼명조/14"` (본문 14~15pt 기준) |

## 주의

- 내용(사실·수치·고유명사)은 절대 지어내지 않는다. 모르면 플레이스홀더 + 질문.
- 게이트를 통과시키려고 사실을 지어내지 않는다. 기대효과 목표치·배경 수치를 모르면 자리표시로 두고 "채울 항목"에 올린다.
- 항목부호는 **수동으로 "1." "가." 를 타이핑하지 말고** 중첩 리스트 깊이로만 표현한다(엔진이 부호·정렬을 넣는다). 단, 보고서 대제목처럼 `#` 헤딩으로 쓸 부분은 헤딩으로.
- 공문서 글꼴·크기·여백·줄간격은 **법령이 강제하지 않는 관행값**이다(편람 근거). 기관 요구가 있으면 `--font/--pt/--line-spacing`으로 조정.
