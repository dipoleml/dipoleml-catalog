# 공문서 구성·윤문 — 설득하는 구조와 게이트

서식과 표기법이 맞아도 결재권자는 두 가지에서 걸린다. **왜 하는지 안 보이는 문서**와 **AI 가 쓴 티가 나는 문서**다.
이 문서는 보고서·계획서를 쓸 때의 구성 설계 기준과, 그것을 검사하는 두 검수기(구성 `logic-lint.ts`, 윤문 `slop-lint.ts`)와
공문서 게이트(`gongmun-gate.ts`)를 다룬다. 표기법은 `gongmun-lint.ts`, 개조식 종결은 `munche-lint.ts`([gaejosik-munche.md](gaejosik-munche.md))가 맡는다.

## 1. 설득하는 구조 — 왜 → 무엇을 → 어떻게

공문의 서론·본론·결론은 장 이름으로 드러난다. "서론·본론·결론"이라고 쓰지 않고 실무 장 이름으로 쓴다.

| 흐름 | 결재권자의 질문 | 장 이름 (행정업무운영편람 표준 목차·실결재 관행) |
|---|---|---|
| 왜 (서론) | 왜 지금, 무슨 근거로? | 추진배경·추진근거·관련근거·법적근거·필요성·현황·문제점·추진경위 |
| 무엇을 (본론) | 그래서 무엇을 하나? | 추진개요·추진방향·개선방안·세부 추진계획·주요내용·검토의견 |
| 어떻게 (결론) | 언제, 누가, 얼마로? 무엇이 나아지나? | 추진일정·소요예산·향후계획·조치계획·행정사항·기대효과 |

문서 꼴에 맞는 뼈대를 고른다(장은 사안에 필요한 것만 — 빈 장을 채우려고 일반론을 쓰지 않는다).

| 꼴 | 뼈대 | 쓰는 때 |
|---|---|---|
| 개선방안 보고 | 추진배경 → 현황 및 문제점 → 개선방안 → 추진일정·소요예산 → 기대효과 → 행정사항 | 문제를 고치자고 할 때 |
| 추진계획 | 추진배경·근거 → 추진개요(기간·장소·대상·예산) → 세부 추진계획 → 소요예산 → 추진일정 → 행정사항 | 사업·행사를 하자고 할 때 |
| 검토보고 | 검토배경 → 주요내용(쟁점) → 검토의견(대안 비교·권고안) → 조치계획 | 요청·안건에 의견을 낼 때 |
| 결과보고 | 관련근거 → 개요 → 추진결과(실적·수치) → 성과와 한계 → 향후계획 | 끝난 일을 보고할 때 |

제목 바로 뒤 요약(`> …하고자 함`)에 **보고 목적과 결론을 먼저** 쓴다(두괄식). 실결재 방침서는 배경 장 없이 이 한 문장이 왜를 맡기도 한다.

### 논리 사슬 — 장과 장이 이어지는가

장 이름이 맞아도 장끼리 따로 놀면 설득되지 않는다. 같은 주제를 생성형 모델에 맡긴 보고서 초안 24건은 장 이름은 모두 표준 틀을
채웠지만 여기서 갈렸다.

1. **배경은 사실로 연다** — 지시(일자)·법령 개정(시행일)·민원·사고 건수 같은 "왜 지금"의 근거. "급변하는 행정환경에 따라"로 열지 않는다.
2. **문제점은 현상과 원인을 가른다** — "야간 단속 공백(원인: 주간 순찰 인력 4명)". 현상만 나열하면 방안이 겉돈다.
3. **문제점마다 방안이 한 짝** — 문제점 ①②③ 순서대로 방안 ①②③. 짝 없는 문제점, 근거 없는 방안을 남기지 않는다.
4. **방안마다 대상·수량·기한** — 그리고 일정·예산 장에서 언제·얼마·누가가 닫힌다.
5. **기대효과는 문제점에서 든 지표의 목표치** — "민원 연 412건 → 200건(51%↓)". "만족도 향상·체감도 제고"는 결재 근거가 아니다.

결재권자가 물을 질문을 미리 문서에 답해 둔다: 왜 지금인가 · 근거 법령은 · 얼마 드나 · 누가 하나 · 다른 방법은 없나(대안 비교) · 반대·위험은.

수치·이름·일자는 지어내지 않는다. 모르면 `○○건`·`2026. ○. ○.` 자리표시로 두고 채울 항목으로 안내한다 — 검수기도 자리표시를 사실 자리로 친다.

## 2. 구성 검수 (`LOGIC_*`)

역할이 매겨지는 장이 셋 이상인 원고(보고서·계획서 꼴)만 판정한다. `#` 은 문서 제목이라 장으로 보지 않고, `##` 이하 헤딩·`□`·
`Ⅰ.`·맨 앞 `1.` 짧은 줄을 장 이름으로 읽는다. 생성 경로에서는 보고서·계획서·개조식·업무보고·서울방침 프리셋에만 돈다(`usesLogicStructure`).

| 코드 | 등급 | 무엇을 잡는가 |
|---|---|---|
| `LOGIC_ESSAY_HEADING` | error | 장 이름이 서론·본론·결론·맺음말·들어가며 |
| `LOGIC_NO_WHY` | error | 방안·전략 장은 있는데 배경·근거·현황·문제점 장도, 목적 문장(`…하고자 함`)도 없음 |
| `LOGIC_NO_HOW` | warning | 방안 장은 있는데 일정·예산·향후계획·행정사항 장이 없음 |
| `LOGIC_ORDER` | warning | 배경·현황이 방안 장 뒤에 옴 (첫 장 "추진개요"는 요약이라 순서 판정 밖) |
| `LOGIC_BASIS_NO_FACT` | warning | 배경·현황 장에 수치·법령·날짜·자리표시가 없음 |
| `LOGIC_PROBLEM_UNANSWERED` | warning | 문제점 항목의 핵심 낱말이 방안·실행 장 어디에도 없음 (표의 "문제점" 칸 포함) |
| `LOGIC_UNGROUNDED` | warning | 개선방안·대책 장은 있는데 현황·문제점 장이 없음 |
| `LOGIC_EFFECT_VAGUE` | warning | 기대효과 장에 목표치가 없음 |
| `LOGIC_EXEC_VAGUE` | warning | 일정·예산 장에 날짜·금액·기한이 없음 (행정사항·추진체계·협조는 제외) |

`LOGIC_PROBLEM_UNANSWERED` 는 낱말 대조라 뜻이 같은 다른 낱말로 쓴 방안은 놓친다 — 방안 첫머리에 `(○○ 공백 해소)` 처럼
어느 문제에 답하는지 적으면 검수기와 결재권자 모두에게 짝이 보인다.

## 3. 윤문 검수 (`SLOP_*`)

| 코드 | 등급 | 무엇을 잡는가 |
|---|---|---|
| `SLOP_PIVOT` | error | 결론적으로·요약하면·정리하면·요컨대 |
| `SLOP_SIGNATURE` | error | 시사하는 바가·주목할 만하다·본질적으로·게임체인저·새로운 지평 |
| `SLOP_HYPE` | warning | 패러다임 전환·한 단계 도약·획기적·극대화 |
| `SLOP_ERA_CLICHE` | warning | 급변하는·중요성이 날로·시대적 요구 — 사실 대신 분위기로 여는 서두 |
| `SLOP_FEEL_GOOD` | warning | 체감도 높은·만족도 향상·삶의 질 제고 |
| `SLOP_VAGUE_OUTCOME` | warning | 숫자·자리표시 없이 강화·제고·구축·활성화로 끝나는 줄이 목록 줄의 15% 이상(10줄 이상 원고) |
| `SLOP_TRANSLATIONESE` | warning | 에 있어서·되어지다·가지고 있다·에 대해서 — 문서 안 3회 이상 |
| `SLOP_TRIAD` | warning | "A, B, 그리고 C" |
| `SLOP_META_LEAD` | warning | 줄 첫머리 "이는·이를 통해·이러한" — 문서 안 2회 이상 |
| `SLOP_EMOJI` | warning | 그림 문자 |
| `SLOP_COLON_HEADING` | warning | 쌍점을 붙인 "제목: 부제" 헤딩 (서울 방침서 "○○ 운영 : 목표" 띄움 꼴은 제외) |

줄표·강조 남발은 표기법 검수의 `AI_EM_DASH`·`AI_BOLD_OVERUSE` 가 이미 잡는다.

## 4. 근거 — 실측

`node bench/gongmun-gate/calib.mjs` 로 다시 잰다(dist 사용, `--show 규칙` 으로 사람 글 적중 줄).

| 표본 | 문서 | 게이트 미통과(윤문·구성 지적 1건+) |
|---|---|---|
| 사람 — 서울 실결재·방침서·기관 공개 문서(`seoul`·`seoul2`·`seoul-old`·`review`·`korea-kr`·`misc`·`hwp5`·`pairs`, `corpus-gen/seoul-bangchim`) | 337 | 20 (5.9%) |
| 사람 — 중앙부처 보도자료(`korea-kr-pairs`·`korea-kr-pairs2`, 생성 경로는 보도자료에 구성 검수를 돌리지 않음) | 501 | 84 (16.8%) |
| AI 초안 — 같은 12개 주제를 생성형 모델 2종에 "개조식 보고서로 써줘"로 맡긴 결과(`bench/gongmun-gate/ai/`) | 24 | 17 (70.8%) |

- error 등급은 사람 글 838건에서 0~1건인 것만 둔다. 사람 글 지적은 대부분 과장 상투구(`SLOP_HYPE` 8건)·시대 상투구(6건)이고 구성 지적은 2건뿐이다.
- 최신 모델 초안은 고전적 상투구("결론적으로", "획기적")를 거의 쓰지 않는다(24건 중 0건). 대신 **기대효과에 목표치가 없음**(14건, 사람 1건),
  **체감·만족도 상투구**(7건, 사람 3건), **배경에 사실 없음**·**짝 없는 문제점**에서 갈린다 — 낱말보다 장 사이 연결이 AI 티의 핵심이다.
- AI 초안 24건은 장 이름으로는 전부 표준 틀(배경 → 현황·문제점 → 방향 → 세부 → 일정 → 예산 → 기대효과 → 향후계획)을 채웠다.
  실결재는 사안에 맞는 장 3~5개(관련근거 → 개요 → 결과, 경위 → 조치계획)로 짧다. 틀을 다 채우는 것이 목적이 아니다.

## 5. 게이트

막는 기준: 표기법·문체는 error 만, 윤문·구성은 경고까지. 표기법·문체 경고는 기관 관행 차이가 섞여 참고로만 낸다.

```bash
kordoc lint 원고.md --gate --preset 보고서      # 결재 올리기 전 최종 점검 — 미통과면 exit 1
kordoc lint 원고.md --slop --logic              # 윤문·구성 지적만 보기 (exit 는 error 기준)
kordoc generate 원고.md -o 보고서.hwpx --preset 보고서 --gate   # 미통과면 파일을 만들지 않음
```

MCP `generate_document` 는 `gate: true` 로 같은 판정을 하고, 미통과면 지적 목록을 돌려준다. 게이트를 켜지 않아도 생성 경고 채널에
윤문(전 프리셋)·구성(보고서·계획서 계열) 경고가 5건까지 붙는다. 라이브러리: `gongmunGate(text, { preset })`·`lintSlopText`·`lintLogicText`.
