# Cross-Code Organizer v0.20.0

CCO v0.20.0 is a practical cross-harness control panel rather than a Claude-only file browser. This release adds current Codex customization inventory, OpenCode and DeepSeek Harness support, a reversible Harness Doctor, unified memory search, safer session distillation, and explicit-opt-in monthly active-install metrics.

## Highlights

### Four harnesses, one local inventory

- Added inventory-first adapters for OpenCode and DeepSeek Harness (DSH).
- Expanded Codex support to honor `CODEX_HOME` and show personal, project, system, and plugin-provided skills; explicit `skills.config` enablement; custom agents; nested local-memory artifacts; user/project `hooks.json`; inline TOML and plugin hook config; hook scripts; standalone `<name>.config.toml` profiles; MCP servers; sessions; history; shell snapshots; and runtime metadata.
- CCO now starts for Codex-, OpenCode-, or DSH-only users even when `~/.claude` does not exist.
- Unsupported mutations remain disabled until an adapter has a verified path and precedence model.

### Harness Doctor

- Added an Effective Context Map that distinguishes direct, ancestor, and global sources only where the harness adapter declares those rules.
- Added an explainable hygiene score with visible deductions rather than a black-box grade.
- Added reversible repair for byte-identical duplicates. Repairs archive and fingerprint the extra copy and support Undo.
- Added preview-first, copy-only skill migration between Claude Code, Codex CLI, OpenCode, and DSH. Existing targets are never overwritten by default.

### Memories and editing

- Added a source-labelled **All Memories** view across Claude projects.
- Added local Markdown body search without sending memory content anywhere.
- Added complete in-dashboard Markdown editing for supported skills, memories, agents, commands, and instruction files.
- Serialized rapid frontmatter saves and reject stale writes to avoid silent edit conflicts.

### Session Distiller repair

- Creates a new independently resumable Claude session and never edits the source transcript.
- Follows the selected session's active `parentUuid` branch, crosses `compact_boundary.logicalParentUuid`, and excludes abandoned rewind branches.
- Generates fresh UUIDs and a complete parent chain.
- Keeps user and assistant text verbatim, summarizes tool protocol, and points omitted large results and images back to an exact private backup and index.
- Fails closed on malformed input and fails open on an ambiguous UUID graph instead of silently dropping conversation records.

Distillation is intentionally lossy for tool payloads. Use it for deterministic, inspectable saved-session cleanup. Claude Code's `/compact` remains better for task-aware summarization during active work.

### Security and reliability

- Bound the dashboard to `127.0.0.1` and reject non-local host headers and cross-site mutations.
- Restricted preview, editing, restore, and backup paths to adapter-approved roots and discovered projects, including Windows drive and UNC boundary handling.
- Added a 1 MiB request-body limit.
- Updated MCP tool registration and declared read-only, destructive, idempotent, and open-world annotations.
- Fixed the YAML `argument-hint` type that prevented the organize skill loading in stricter clients (#35 / #34).
- Added further Windows and external-project path regression coverage (#17 and #33).
- Updated dependencies; `npm audit --omit=dev` reports zero known vulnerabilities at release time.

The activation-probe scanner remains a research preview. Its adversarial corpus is deliberately excluded from the npm package; the shipping package contains the existing static scanner only.

### Privacy-preserving product metrics

- Anonymous metrics are disabled by default and require explicit opt-in in Harness Doctor.
- When enabled, CCO sends at most one deduplicated activity signal per installation and UTC month. It records the selected harness at the time of the first successful submission that month.
- The payload contains only the schema version, month, a 128-bit pseudonymous ID that rotates monthly, CCO version, and an allowlisted harness ID.
- Paths, names, prompts, file contents, sessions, credentials, inventory counts, and local event counts are never sent.
- The collector exposes monthly totals by version and harness; detailed activity remains local for up to 30 days.

See [PRIVACY.md](https://github.com/mcpware/cross-code-organizer/blob/v0.20.0/PRIVACY.md) for the exact payload and endpoint.

## CLI and packaging

- Added `cross-code-organizer --help` and `--version`.
- Updated the auto-installed `/cco` skill for the cross-harness dashboard and
  made it follow the exact local URL printed by CCO instead of assuming port
  3847.
- Browser auto-open now waits for the server and uses its actual fallback port;
  process execution no longer interpolates the URL through a shell.
- Corrected npm executable and repository metadata.
- Migrated the publish workflow to npm trusted publishing with GitHub OIDC and provenance.
- Pinned release actions to immutable commits and added checksum verification for the MCP Registry publisher archive.
- Added the official MCP Registry validator as a required release gate. Publishing is safely rerunnable, registry failures stop the release instead of being silently ignored, and the GitHub Release is created only after npm and MCP Registry both expose the new version.
- Synchronized npm, Claude plugin, and MCP Registry versions at `0.20.0`.
- The npm tarball contains 49 allowlisted runtime/documentation files and excludes research datasets and local Session Distiller experiments.
