# Maintain: bug filing and drift-note retirement (gated reference)

> Read from maintain.md only when this pass found a product bug, or Phase 1 found open drift memos.

## Product bug

**Reporting a product bug.** File to the bug memory track when memory is enabled. Write the body under `$RUN_DIR` first, then file with the full required field set: `"$FLOWCTL" memory add --track bug --category <bug category, e.g. runtime-errors|ui|integration> --title "<feature>: <one-line symptom>" --module <surface or component> --body-file <path> --json` (`--category` and `--title` are required - a call without them exits nonzero, and under `set -e` that would end the run without its terminal verdict). Invoke it failure-tolerant under `set -e` (e.g. `if _out="$("$FLOWCTL" memory add ...)"; then <parse>; else <record in run notes>; fi`) - a nonzero exit must never end the run before its terminal verdict. First run the same `memory add` fields with `--check-overlap --json` (no write). Overlap scoring stays on (never `--no-overlap-check`); judge the returned `matches`. When a prior entry is the same bug rediscovered, issue one `memory add --update <id>` with those fields; otherwise issue one normal add. Do not create a duplicate to discover overlap. Not `memory upsert`: these titles are free-form one-line symptoms, not a stable identity, so exact-title find-or-create would miss a re-phrased rediscovery and file a duplicate - upsert is for stable-title memos like the `feature-map-drift` track. Parse the JSON with `jq` or python. Memory disabled: record the finding in the run notes only. Either way the finding stays out of the `changed` diff.

## Drift-note retirement

**Drift-note retirement.** For each Phase 1 drift memo whose named route proved this pass (corrected or already matching), mark it stale per the contract's "Writers and drift notes" section: `"$FLOWCTL" memory mark-stale <entry-id> --reason "route re-proven <date> at <short commit>" --json`, failure-tolerant under `set -e` like bug filing. First require `git status --porcelain -- <path>` to be empty for that note (`path` from `open_drift` in `$RUN_DIR/features-status.json`); a note with uncommitted edits stays open and is named in the run notes, so Phase 6's staging and the `BLOCKED` restore only ever touch this run's own retirement. Keep each retired `path` for Phase 6 staging. A memo whose route did not prove stays open. An `unmapped` memo (title `drift: <surface>/<slug> unmapped`, filed by work when it could not tie a changed surface to a feature file) names no route: retire it the same way once this pass has reconciled the surface it names, either by proving a feature file that now covers it or by confirming it is not user-facing. Memory disabled: nothing is marked.
