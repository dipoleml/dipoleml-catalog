Writ

A local rule-enforcement service for Claude Code. On every prompt and every file write it answers two questions: which rules apply right now, and is this write allowed yet. This page is data-backed — every number and node below is read live from the running daemon.

Relocate oversight; don't remove it. The gate is the product.

Writ never automates self-approval. A human token-gates any write of canon, and the agent cannot forge the approval that advances a workflow phase or promotes a rule into the corpus. Where the agent could otherwise approve its own work, a human-held token sits in the way.

The three pieces

One design rule underpins them all: Neo4j is canonical; the bible/ Markdown tree is a derived, exported view. When they disagree, the graph wins on reconcile.

Librarian — retrieval

A hybrid RAG pipeline retrieves only the rules relevant to the current task, so rule text stays out of the context window when it does not apply.

Process-keeper — hooks & gates

Thin bash hooks intercept the Claude Code tool lifecycle; a per-session state machine tracks mode / phase / budget / gates and blocks writes until the gate is satisfied.

Canonical store — Neo4j

The knowledge graph holds all rules and methodology nodes: 13 node types joined by 19 edge types. The bible/ Markdown is a derived view, never authoritative.

Modes & gates

Writ runs a per-session state machine with five modes.

ModeWhat it is for
conversationDefault. No write gating.
debugRoot-cause investigation; source edits blocked until a root cause is populated.
investigateEvidence-grounded audit / explore / research (one engine, lens set per invocation).
reviewRead-and-assess; no gated writes.
workThe gated build workflow.

Work mode has two gates

planningwrites blocked
Gate phase-a · plan validated
testingwrites blocked
Gate test-skeletons
implementationwrites allowed
complete
The token (no self-approval). A phase advance requires a gate token at /tmp/writ-gate-token-<session_id>. The approval hook writes it only when your prompt matches an approval pattern — input the agent cannot fabricate. The token is consumed on a successful advance, so one human approval authorizes exactly one advance. The same token gates promoting a rule into the corpus.

Self-authoring & graduation

A node's provenance is one of four states. hand-authored is a distinct entry state (the markdown corpus at rest); the other three form the self-authoring path. Statistical crossing is not approval — a human gate stands between a candidate and the corpus.

hand-authored (corpus entry state)
proposed
→
graduation_pending
→
human gate
→
graduated

proposed is set by /propose (and writ add). A frequency crossing (50 observations, ≥0.75 positive ratio) flips it to graduation_pending — a statistical flag, never an authority change and never a write to bible/. Promotion to graduated runs through the same agent-unforgeable token gate as a phase advance; the human approves as-is or edits at the gate, and an edit re-runs the structural gate before export.
